# Переносимый локальный стенд

Пользователь поручил реализовать в этой сессии общий репозиторий развёртывания с нуля в Afonenko-Course-Tools. Согласован подход: один основной Compose, опубликованные приложения, обычные конфигурации, одноразовая инициализация и инструкция. До 22:00 основной приоритет сохраняется у действующего локального стенда и полной приёмки курса; VM обновляется завтра.

## Результат

Из чистого клона на Linux/amd64 с Docker Compose можно запустить отдельный PrairieLearn с Gateway, HTTPS-прокси и тестовой Moodle. Курсы задаются обычными каталогами native PrairieLearn; Java, числовые ID и Moodle учреждения в код не зашиваются. Для проверки первого запуска допустим маленький пример в родном формате PrairieLearn. Настоящие экспорты подключаются без изменения приложения.

Один compose.yml описывает сервисы, сети, хранилища и порядок первоначальной настройки. .env.example содержит только настройки машины и публичные значения. Секреты генерируются локально и не попадают в Git. Сертификат создаётся для нового стенда, его доверие на ноутбуке пользователь настраивает отдельно; системное хранилище автоматически не меняется.

Platform и Gateway остаются источниками приложений и образов. Новый репозиторий хранит только развёртывание и небольшую инициализацию штатными средствами. Для Moodle нужен воспроизводимый Dockerfile либо подходящий официальный образ; локальный preflight-образ и прежние рабочие деревья недопустимы как зависимость.

Рассмотрены копирование текущего снимка и новый слой управления развёртыванием. Выбран обычный Compose: снимок не проверяет старт с нуля, а собственный менеджер не нужен. Рабочий стенд пользователя и его данные не используются как экспериментальные хранилища.

## Границы

- Первоначальная установка отличается от повторного старта: повтор не пересоздаёт БД, пользователей, ключи и регистрации.
- Экспорт и выполнение тестов решений не входят в запуск серверов; входом служит готовый курс.
- Нет новых форматов курса, API, очередей, хеширования, реестров доказательств или копий приложений.
- Все настройки Workspace и HOST_JOBS_DIR явные; его запуск и сохранение проверяются отдельно.
- Порты и Compose project name отдельные от действующего стенда; существующие контейнеры, сети и volumes не изменяются.
- Только S1 выполняет локальные Docker build/pull/up и тяжёлые проверки после оценки памяти. Остальные чаты готовят исходники, конфигурации и адресные лёгкие проверки.

Готовность подтверждается новым запуском с пустыми хранилищами, входом из новой тестовой Moodle, загрузкой native-курса и сохранением состояния после повторного up. Возможность Workspace отмечается отдельно фактическим результатом. Непроверенный запуск не называется готовым комплектом.
