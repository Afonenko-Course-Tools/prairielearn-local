# Переносимая локальная инфраструктура

Последнее прямое поручение пользователя от 6 ноября ограничивает новый репозиторий инфраструктурой, не зависящей от будущей CI/CD. Доставка курса разрабатывается отдельно. Сегодняшний срок — 22:30; действующая VM обновляется завтра.

## Результат и границы

Из чистого клона на Linux/amd64 с Docker Compose запускается отдельная инфраструктура PrairieLearn и тестовой Moodle. Основной Compose описывает сервисы, сети, постоянные хранилища, healthchecks и первоначальную настройку. Published Platform/Gateway остаются источниками приложений; Moodle собирается из воспроизводимого официального источника. Локальные рабочие деревья, прежние контейнеры и непубликуемый preflight-образ зависимостями не служат.

В репозитории остаются TLS, секреты и обычные конфигурации приложений; узкая первоначальная инициализация native administrator разрешена только в пустой локальной БД, через существующие native модели и аудит. Повторный старт не пересоздаёт аккаунты, ключи, регистрацию и хранилища. Системное доверие CA устанавливается пользователем отдельно.

Gateway/Bridge используют существующие конфигурационные форматы. Реальные привязки institution/course/instance предоставляет внешняя процедура; базовый запуск не выдумывает numeric IDs и не требует наличия курса. Конфигурационный вариант с Gateway/Bridge подключается после получения действительных настроек. Workspace подключается отдельным стандартным override с выделенным Docker daemon; обязательный socket не блокирует базовый запуск.

## Что исключено

- Экспорт Quarto, проверка решений, загрузка и обновление курсов, управление поставками и конфигурацией bindings.
- Новый importer, local course registry/receipt, COURSE_REPOSITORY/COMMIT и чтение delivery ради запуска базовой инфраструктуры.
- Собственный разбор .env, новый формат конфигурации, протокол, API, очередь, менеджер Compose или реестр доказательств.
- Будущие CI/CD workflow и планы их реализации: это отдельная работа и отдельное предложение в общем отчёте.

Обычные Platform CLI остаются внешней существующей границей публикации курса. Репозиторий не определяет контракт будущей CI/CD.

## Приёмка

Root проверяет исходники, соответствие границам и отсутствие машинных данных. Только S1 запускает Docker после оценки памяти; основной пользовательский стенд не останавливается. Чистый запуск, повторный up с прежним состоянием и доступность сервисов подтверждаются фактическими результатами. LTI и Workspace принимаются отдельно при действительной конфигурации; готовность уже существующего стенда не заменяет новый запуск с нуля. Непроверенная возможность явно остаётся непроверенной.
