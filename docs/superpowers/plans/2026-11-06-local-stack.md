# План локальной инфраструктуры

Пользователь поручил реализацию и затем сузил область до инфраструктуры, независимой от будущей CI/CD. Повторное общее подтверждение не требуется. У каждого файла один владелец; root интегрирует Git и PR.

## S2 — Compose и конфигурации

Файлы: compose.yml, стандартные overrides, .env.example, config/, scripts/init-config.py, .gitignore, .dockerignore.

- Сохранить опубликованные приложения, постоянные хранилища, отдельные порты и healthchecks.
- Оставить только подготовку общих конфигураций, ключей/TLS и host permissions. .env разбирает Compose; число обязательных параметров минимально.
- Удалить course import, registry, delivery parsing и зависимости base up от курса. Gateway/Bridge подключаются с действительной внешней конфигурацией, без выдуманных IDs.
- Workspace и required socket вынести в отдельно подключаемый стандартный override.
- Передать root замороженный diff и команды синтаксической проверки; Docker не запускать.

## S3 — тестовая Moodle

Файлы: moodle/, scripts/moodle-bootstrap.php.

- Воспроизводимый официальный источник и штатные Moodle CLI/API.
- Создание тестовых ролей и регистрации при первой установке; повтор сохраняет credentials/registration.
- Секреты только в локальном state, без реальных институциональных данных и Java IDs.
- PHP/sh syntax и независимый просмотр стыка с конфигурацией S2; Docker не запускать.

## S5 — первоначальный native administrator и инструкция

Файлы: scripts/bootstrap-admin.mjs, tests/bootstrap-admin.test.mjs, README.md.

- Извлечь только native empty-DB actor/admin bootstrap с аудитом, lock/transaction и сохранённой identity.
- Повтор проверяет ту же роль/UID/ID; не присваивает права заново и не усыновляет существующую историю при утраченном state.
- Исключить import-course wrapper, course-import.json, bootstrap/sync orchestration и генерацию bindings.
- README описывает только инфраструктуру, TLS, состояние, остановку и отдельные возможности. Публикация курса — внешние существующие Platform CLI, будущая CI/CD не реализуется.

## Root и S1 — интеграция

- Root сверяет границы, секреты, пути и согласованность сервисов, затем сохраняет reviewable PR.
- S1 проверяет память и текущую нагрузку; build/up нового проекта выполняются отдельно от основного стенда и не создают OOM.
- Подтвердить чистый запуск и повтор с прежними данными; отдельно обозначить фактический объём LTI/Workspace.
- Итоговые README, PR и общий отчёт отражают результат проверки, а не предполагаемую готовность.
